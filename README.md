# ريبو · التربية الفنية — المرحلة المتوسطة / Rebo

تطبيق تعليمي عربي (RTL) كامل لحاسوب ويندوز ولأجهزة أندرويد، يقدّم **دليل معلم
التربية الفنية للمرحلة المتوسطة** (الصفوف الأول والثاني والثالث) بوصفه تجربة
تفاعلية: فهرس، وحدات، خطط دروس، بنك أسئلة، ومختبر فني — **يعمل دون اتصال
بالإنترنت بالكامل**.

- ١٣ وحدة تعليمية · ٩ خطط دروس · ٧٦ سؤال تقويم · ٢٠ صفحة فهرس
- لوحات وصفحات مصوّرة من الدليل، مع لوحة توليدية لكل وحدة
- واجهة عربية RTL بخطوط مدمجة (Cairo / Kufi / Amiri) — لا تُحمَّل أي موارد من الشبكة

## المخرجات الجاهزة

| الملف | المنصة | الحجم | الوصف |
|---|---|---|---|
| `dist/rebo-android-v1.0.0.apk` | أندرويد 5.0+ (minSdk 21) | ~2.0 MB | موقّع (v1+v2+v3)، محاذاة zipalign، يعمل بلا إنترنت |
| `dist/Rebo-Setup-1.0.0.exe` | ويندوز 10/11 (x64) | ~3.2 MB | مثبّت للمستخدم الحالي (لا يحتاج صلاحيات مدير): اختصارات + إزالة |
| `dist/Rebo-Windows-1.0.0/` | ويندوز 10/11 (x64) | ~4.0 MB | نسخة محمولة: `Rebo.exe` + `WebView2Loader.dll` + `www/` |
| `dist/Rebo-Windows-1.0.0-portable.zip` | ويندوز | ~2.2 MB | النسخة المحمولة مضغوطة |
| `dist/SHA256SUMS.txt` | — | — | بصمات التحقق للملفات أعلاه |

**الاسم الظاهر للتطبيق:** «ريبو · التربية الفنية» · **معرّف أندرويد:** `com.techtouch.rebo`

### التثبيت

- **أندرويد:** انقل ملف APK إلى الجهاز ثم افتحه، واسمح بتثبيت التطبيقات من هذا
  المصدر عند الطلب. التطبيق لا يطلب صلاحية الإنترنت إطلاقًا.
- **ويندوز (مثبّت):** شغّل `Rebo-Setup-1.0.0.exe`. يتثبّت في
  `%LOCALAPPDATA%\Programs\Rebo` ويُنشئ اختصارًا على سطح المكتب وفي قائمة ابدأ،
  ويظهر في «الإعدادات ← التطبيقات» للإزالة. لا يحتاج صلاحيات مدير.
- **ويندوز (محمول):** افتح `Rebo-Windows-1.0.0\Rebo.exe` مباشرة.
- **متطلب وحيد على ويندوز:** *WebView2 Runtime* — مثبّت مسبقًا في ويندوز 11
  وفي معظم تحديثات ويندوز 10. إن لم يكن موجودًا يظهر تنبيه عربي مع رابط التحميل
  الرسمي من Microsoft، ولا ينهار التطبيق.

## بنية المستودع

```
app/www/            التطبيق نفسه (HTML/CSS/JS + خطوط + لوحات) — يعمل بأي متصفح
app/android/        غلاف أندرويد: AndroidManifest + MainActivity (WebView) + res
app/windows/        غلاف ويندوز: Win32 + WebView2 (src, loader, res, setup)
app/pipeline/       خط إنتاج المحتوى: .docx ← data.js + media
tools/              أدوات البناء الرسمية (Android Build-Tools) + مساعدات
keystore/           مفتاح توقيع الإصدار
build-android.sh    بناء APK موقّع
build-windows.sh    بناء نسخة ويندوز + المثبّت
build-all.sh        الاثنان معًا
dist/               المخرجات الجاهزة
```

## بوابات الجودة

```bash
python3 tools/check.py          # يفحص: الإصدار، المحتوى، الأصول، JS، APK، EXE
```

كل بناء يتحقق من مخرجاته بنفسه؛ لا يُعلن النجاح إلا بعد اجتياز:

| البوابة | ما تتحقق منه |
|---|---|
| `sync-version --check` | كل ذكر للإصدار مطابق لـ `package.json` |
| `check.py: content` | ١٣ وحدة، ٥٥ موضوعًا، ٧٦ سؤالًا بمفاتيح إجابة، ١٩ لوحة، ٩ خطط |
| `check.py: assets` | كل ملف يشير إليه HTML/CSS/data.js موجود فعلًا |
| `check.py: javascript` | `node --check` على كل ملفات JS |
| `build-android` | zipalign ٤ بايت + توقيع v2/v3 مؤكَّد + badging مطابق للإصدار |
| `build-windows` | PE 64-bit GUI + manifest (DPI/Common Controls) + أيقونة + نسخة + حمولة |
| `verify-pe --expect-zip` | قارئ الحمولة في المثبّت يعيد نفس البايتات التي يراها قارئ zip |

## بناء قابل للتكرار (Reproducible build)

البناء حتمي: نفس المصادر + نفس قيمة `SOURCE_DATE_EPOCH` ⇒ **ملف APK مطابق بايتًا
ببايت**. تحقّقنا من ذلك بتوقيعين متتاليين متطابقين في البصمة.

```bash
SOURCE_DATE_EPOCH=1767225600 bash build-android.sh
sha256sum dist/rebo-android-v1.0.0.apk   # نفس البصمة في كل تشغيل
```

هذا يجعل التحقق من المخرجات ممكنًا لأي طرف ثالث، ويجعل `dist/SHA256SUMS.txt`
قابلًا للمقارنة.

## إعادة البناء

### 1. المحتوى (اختياري — المخرجات محفوظة في المستودع)

```bash
python3 app/pipeline/build_content.py
```

يقرأ ملفات `.docx` في جذر المستودع، ويكتب `app/www/js/data.js`، ويستخرج لوحات
الدليل إلى `app/www/media/`. يحتاج فقط Python 3 (و`Pillow` لتقسيم اللوحات
المركّبة؛ بدونه يُحفظ كل مسح كصورة واحدة).

### 2. أندرويد

```bash
export JAVA_HOME=/path/to/jdk17+
bash build-android.sh
```

يعتمد على أدوات Google الرسمية:

| الأداة | المصدر |
|---|---|
| `aapt2` · `d8.jar` · `apksigner.jar` | Android SDK **Build-Tools 34.0.0** |
| `android.jar` | Android SDK **Platform 34** |
| `ecj.jar` | Eclipse JDT (مضمّن في Build-Tools) |
| `zipalign` | مكافئ داخلي `tools/zipalign.py` (لأن الثنائي غير متوفر لكل المنصات) |

انظر `tools/README.md` و`tools/fetch-tools.sh` لطريقة إحضار الأدوات من
`developer.android.com`. لا يستخدم البناء Gradle ولا يُجري أي تنزيل شبكي.

### 3. ويندوز

```bash
ZIG=/path/to/zig bash build-windows.sh
```

- المُصرِّف: `zig c++ -target x86_64-windows-gnu` (mingw-w64 + UCRT)
- واجهة العرض: `webview.h` (MIT) + `WebView2Loader.dll` **مبني من المصدر**
  (`app/windows/loader/`) — لا يُعاد توزيع أي ثنائي من Microsoft
- المثبّت: `app/windows/setup/setup.cpp` — مثبّت مستخدم مُكتفٍ بذاته يحمل
  التطبيق داخله كأرشيف `RCDATA`، ولا يحتاج NSIS ولا صلاحيات مدير

## سلوك التطبيق الداخلي

- تنقّل قائم على `location.hash` (`#home`, `#index`, `#grade/…`, `#unit/08`,
  `#plans`, `#plan/…`, `#intro`, `#studio`, `#quiz`, `#settings`) — يعمل من
  `file://` داخل الغلافين دون أي خادم.
- **اختيار الصف أول مرة:** عند أول تشغيل يطلب التطبيق اختيار الصف (الأول /
  الثاني / الثالث المتوسط) ويُحفظ الاختيار. بعد الاختيار لا يظهر إلا محتوى ذلك
  الصف: الوحدات، الفهرس، الخطط، أسئلة التقويم، البحث، وقائمة التنقّل. أي رابط
  مباشر لوحدة من صف آخر يُرفض برسالة، والوحدة العامة (مفردات الأنشطة المسرحية)
  تُعرض مع كل الصفوف لأنها غير مرتبطة بصف. الغيّر الصف من شارة الصف في الشريط
  العلوي أو من «الإعدادات ← الصف الدراسي».
- **حجم الخط في كل صفحة:** شريط قراءة (أ− / أ / أ / أ / أ+) في أعلى كل صفحة
  محتوى، بأربع درجات (صغير، عادي، كبير، أكبر) تُحفظ بين الجلسات. كل مقاسات
  النص في `app.css` بوحدة `rem` والمضاعف على `html[data-fs]` (`--ui-scale`)،
  لذلك تتغيّر كل الواجهة معًا ولا يُكتب أي `font-size` بالبكسل.
- **سطر واحد لكل سطر:** عناوين الصفوف والفهرس وبطاقات الوحدات تُقصّ بـ
  `text-overflow:ellipsis` بدل الالتفاف إلى سطر ثانٍ أو توسيع الصفحة، ومجموعات
  الأقراص تنتقل أفقيًا على الهاتف.
- زر الرجوع في أندرويد يُمرَّر إلى الصفحة عبر `window.ReboNav` ثم يعود إلى
  الصفحة السابقة، ولا يخرج من التطبيق إلا في الجذر.
- روابط المواقع الخارجية تُفتح في المتصفح، لا داخل WebView.

## الفرع والتكامل المستمر

«ريبو» مشروع مستقل يعيش على فرعه الخاص `arena/7c94fe0a-rebo`، ولا يُدمج في `main`
(الذي يحتوي تطبيقًا آخر للمادة نفسها). دورة البناء والحزم كاملة داخل هذا الفرع.

| المسار | الوظيفة |
| --- | --- |
| `.github/workflows/apk.yml` | بناء APK موقّع + حزمة ويندوز على كل دفعة، وإرفاق الملفات بإصدار عند وسم `rebo-v*` |
| `tools/ci-setup-android.sh` | تنزيل أدوات Android الرسمية (aapt2 · d8 · apksigner · android.jar · ecj) إلى `tools/` |
| `tools/ci-setup-zig.sh` | تنزيل Zig لبناء مضيف ويندوز على Linux |
| `build-android.sh` / `build-windows.sh` | نفس السكربتات المستخدمة محليًا — لا منطق خاص بـ CI |

ملفات المخرجات الجاهزة محفوظة أيضًا في `dist/` داخل الفرع، وصفحة تنزيل عربية في
`dist/index.html`.
