# خطة الفحص والجودة

## 1. المحتوى (قابل للتنفيذ محلياً، نُفِّذ)

```bash
python3 tools/build_content.py
python3 tools/verify_content.py
```

- الطبعات: `units: 11 | topics: 37 | questions: 73 | lessons: 4 | plates: 10 | drawings: 14`.
- المتحقّق: **1404 فحوص** — وجود كل جملة مصدرية، اكتمال الموضوعات، تطابق الإجابات مع الشواهد،
  اكتمال الأهداف (11) والطرائق (9)، تطابق اللوحات مع صفحاتها، **تطابق صور الموضوعات الأربعة عشر
  مع صفحاتها بايتاً ببايت** وربط كل رسم بموضعه من المنهج، وغياب الاقتطاع «…».
- فحص إضافي: كل مسار أصل مذكور في JSON موجود على القرص (يُعاد أيضاً في `test/content_test.dart`).

## 3. فحص الواجهة اليدوي

| الحالة | المتوقع |

| حجم الخط 50٪ و120٪ | لا اقتطاع في العناوين، التفاف صحيح للجداول |
| الوضع الليلي | تباين كافٍ، الرسوم مقروءة، شرائط السنوات واضحة |
| تدوير الشاشة / تغيير الحجم | استمرار الحالة، عدم فقدان موضع القراءة |
| إعادة تشغيل التطبيق | عودة آخر وحدة، المفضلة، ونتائج الاختبارات، والصف المختار (بلا شاشة اختيار ثانية) |
| تغيير الصف | اختفاء وحدات الصف السابق من الفهرس والبحث واللوحات ورسوم الموضوعات والمصطلحات فوراً |
| طباعة الأسئلة على أندرويد وويندوز | اختيار وحدة، ثم وحدتين، ثم الكل؛ معاينة A4 تُظهر الأسئلة المختارة فقط بلا إجابات، مرتبة صح وخطأ ثم اختيارات ثم تعداد، مع بقاء الخط ١٢ والعناوين ١٤ |
| ترويسة الرئيسية على 390 بكسل | الشعار والأدوات في صف، والعنوان وعنوانه الفرعي تحته، بلا تزاحم أو أعمدة كلمات |
| إحصاءات الرئيسية (وحدات/موضوعات/أسئلة/لوحات) | أربع خانات في صف واحد، كل تسمية بسطر واحد عند أي حجم خط |
| ترويسة الوحدة | الصف في سطر، ثم «رقم الوحدة + القالب + زمن القراءة» في سطر واحد ثابت الحجم |
| مصطلحات الوحدة | ثلاثة مصطلحات في كل صف عند أي حجم خط |
| رسوم الموضوعات في القارئ | كل رسم فوق الموضوع الذي يخدمه مباشرة، بلا فجوة ولا تكرار |
| معرض الصور | مجموعتان (لوحات الوحدات / رسوم الموضوعات) وفواصل لكل وحدة، وعمود واحد على 390 بكسل |
| سطر شرح الرسم + «تكبير» | سطر واحد مضغوط، ومفتاح الألوان في سطر واحد |

## 4. فحص المخرجات (آلي داخل CI)

- **APK**: `aapt dump badging` يتحقق من الحزمة `com.techtouchai.mirsam`، `minSdk 24`، `targetSdk 36`،
  ثم يتأكد من وجود JSON المحتوى والخطوط والرسوم واللوحات و`libapp.so` و`libflutter.so` داخل الحزمة.
- **ويندوز**: فحص محتويات ZIP (EXE + `flutter_windows.dll` + `data\flutter_assets\…`)، ثم **تشغيل
  `mirsam.exe` فعلياً** على مشغّل ويندوز والتأكد من بقائه حياً 20 ثانية وإنشائه نافذة.
- الأثران يُرفعان مع `SHA256SUMS.txt` و`BUILD-INFO.txt`.

## 5. نتائج التشغيل

نجحت وظائف CI الأربع على الفرع: تحقق المحتوى (1404 فحوص)، `dart analyze --fatal-warnings`،
`flutter test` بكامل ملفاته (بما فيها اختبارات اختيار الصف وحجم الخط في كل شاشة وتخطيط شاشة الاختيار)،
وبناء APK، وبناء حزمة ويندوز — التشغيل `43418734782` على الالتزام `adf2e4d`.

### تحقق قسم الطباعة في بيئة العمل الحالية

- وُلّدت مستندات PDF فعلياً لجميع اختيارات الوحدات غير الفارغة في الصفوف الثلاثة (٢١ اختياراً)؛
  كل نتيجة صفحة A4 واحدة بخطي ١٢ و١٤ نقطة، مع الخط العربي المضمّن وفحص المحارف المستخدمة.
  واستُكمل سؤال تجريبي طويل على خمس صفحات دون فقد كلماته.
- نُفّذت ١١ حالة من اختبارات خطة الطباعة وPDF باستخدام Dart مستقل ومكتبتي `test_api` و`matcher`،
  مع بدائل اختبارية لخدمات Flutter والطابعة؛ هذا ليس تشغيل `flutter test` ولا اختباراً للطباعة الفعلية على جهاز.
- فُحصت ملفات التغيير بتحليل Dart مع مصادر Flutter، بإعداد محلي مؤقت لا يحل محل تحليل المشروع الكامل.

## 6. ما لم يُنفَّذ في هذه البيئة

لا يوجد Flutter SDK في بيئة العمل (تعذّر الوصول إلى مستودع تنزيل SDK)، لذلك:

- لم يُشغَّل `flutter analyze` ولا `flutter test` ولا أي بناء APK/EXE محلياً.
- الترجمة والتحليل والاختبارات والبناء تُنفَّذ في `.github/workflows/ci.yml` على GitHub Actions
  بمخزن Flutter الرسمي 3.35.0.
- لا محاكي أندرويد في CI، لذلك لا يُجرَّب APK بتثبيت وتشغيل فعلي؛ التحقق منه بنيوي (حزمة + موارد + مكتبات).
  الفحص العملي الكامل للتطبيق يتم على جهاز أندرويد، والفحص العملي لويندوز مُنفَّذ فعلياً في CI.

هذا مذكور صراحةً في التقرير النهائي: لا يُدّعى نجاح بناء أو اختبار قبل تنفيذه فعلياً.
